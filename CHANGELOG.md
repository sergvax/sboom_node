# Changelog

Все заметные изменения проекта. Формат — [Keep a Changelog](https://keepachangelog.com/ru/1.1.0/),
версии — [Semantic Versioning](https://semver.org/lang/ru/).

## [1.3.2] — 2026-11-13

### Исправлено

- **Понятный запуск, когда сервер уже работает.** Второй `npm start` больше не
  падает со стеком `EADDRINUSE`: если на порту отвечает наш `/api/state`,
  выводится адрес запущенного экземпляра и подсказка. Проверка порта выполняется
  до подключения к колонкам, поэтому второй процесс не открывает лишние сессии.
- **`npm run restart`** — останавливает процесс на порту (SIGTERM, при
  необходимости SIGKILL) и запускает сервер заново в фоне с логом
  `data/server.log`. Решает ситуацию, когда старая копия осталась висеть после
  закрытия терминала и работала со старым кодом.
- **`npm run restart -- --stop`** — только остановить сервер.

## [1.3.1] — 2026-11-13

### Изменено

- **Остановка мультирума больше не блокирует интерфейс.** `stopNativeMultiroom()`
  отправляет паузу всем участникам группы и сразу возвращает состояние
  `stopping` с оценкой `dissolveAt`; роспуск (таймер прошивки, 11–15 с)
  дожидается в фоне (`nativeStopTask`). Ответ `POST /api/multiroom/native/stop`
  — ~10 мс вместо 15–20 с.
- Роли колонок во время роспуска опрашиваются каждые 400 мс (было 700),
  поэтому блокировка `play`/`next`/`prev`/`seek` снимается в тот же момент,
  когда прошивка сообщила `mode = NONE`.
- Повторная пауза отправляется только как страховка — если за 15 с группа
  не исчезла.
- Сообщение при попытке запустить звук во время роспуска теперь с реальным
  остатком: «Мультирум ещё выходит из группы — попробуйте через N с».
- В панели «Все колонки» во время остановки показывается обратный отсчёт
  («группа распускается, осталось ~N с»).

### Добавлено

- `docs/multiroom-stop.md` — разбор того, как прошивка распускает группу,
  замеры таймингов и список проверенных путей мгновенного выхода.
- Диагностические скрипты `diag/mr-*.mjs`: тайминги роспуска, A/B «одна пауза
  против двух», перебор команд `op=16`, проверка StarCommand `stop_multiroom`,
  поведение запуска трека во время роспуска.

### Удалено

- Временный эндпоинт `POST /api/multiroom/native/star-stop`: StarCommand
  `stop_multiroom` прошивкой 1.102–104 принимается, но группу не распускает.

## [1.3.0] — 2026-11-12

### Удалено

- **Программный (deeplink) мультирум удалён из проекта полностью.** Единственный
  мультирум — нативный SberCast: группу строит прошивка по `START_MULTIROOM`
  (`op=16`, cmd=8), синхронизацию звука выполняет сама колонка.
- `lib/multiroom.js` целиком (`MultiroomController`: фаза по переходам секунд,
  EMA-лаг `seek`, монитор выравнивания, mute при входе в группу, перехват
  `next` по `msgId`) вместе с тестами `test/multiroom.test.js` и
  `test/multiroom-latency.test.js` и e2e-тестами программного мультирума.
- Эндпоинты `POST /api/multiroom/start`, `POST /api/multiroom/stop`,
  `POST /api/multiroom/leave`. В снимке состояния больше нет поля `multiroom` —
  остались `nativeMultiroom` и роли каждой колонки (`multiroom.mode`).
- Перенаправление команд внутри группы (`MULTIROOM_PROPAGATE`): `command()` и
  `groupCommand()` больше не перехватывают play/pause/next/prev/seek и не
  отправляют их источнику — транспорт ведёт прошивка.
- `SpeakerManager.startMultiroom` / `stopMultiroom` / `leaveMultiroom`, guard
  «сначала выключите программный мультирум» и `forget()` при удалении колонки.

### Изменено

- `playContent` запускает контент на одной колонке. Если она ведомая в нативной
  группе, запуск отклоняется с понятным сообщением: контент нужно запускать на
  мастере, группа подхватит тот же deeplink.
- Добавлен тест: в нативной группе запуск контента на мастере проходит, на
  ведомой — блокируется.

### Исправлено

- Гонка при генерации сертификата мок-колонки: `node --test` запускает тестовые
  файлы параллельно, и общий `mock/certs` иногда давал `ERR_OSSL_X509_KEY_VALUES_MISMATCH`
  в CI. Теперь сертификат создаётся один раз на процесс в отдельном temp-каталоге.

## [1.2.3] — 2026-11-12

### Изменено

- **Единый чип «МУЛЬТИРУМ» на всех колонках группы.** Вместо парных
  «НАТИВНЫЙ МАСТЕР» / «НАТИВНЫЙ МУЛЬТИРУМ» на карточках участников группы
  теперь один короткий чип: одинаковый размер на каждой карточке.
  Роль (мастер/ведомая) осталась в подсказке при наведении.
- **Карточки выровнены по высоте** (`align-items: stretch` в сетке, подвал —
  через `margin-top: auto`). Раньше `align-items: start` давал разным
  содержимым (чип/буферизация) — разную высоту карточек в одном ряду, и UI
  «плыл» при запуске мультирума.
- Обновлён UI-тест под единый чип `мультирум`.

## [1.2.2] — 2026-11-12

### Исправлено

- **«Стоп» нативного мультирума теперь действительно выводит колонки из
  группы.** Раньше остановка опиралась на сохранённый `masterId` и могла
  вернуть `idle`, хотя колонки продолжали играть в группе: выбранный после
  этого трек снова звучал на всех колонках. Теперь стоп:
  - находит группу по живым `multiroom.mode`, даже если менеджер считает
    себя `idle` (например, после перезапуска сервера);
  - ставит мастера на паузу и ждёт, пока **все** колонки вернутся в `NONE`,
    прежде чем показать «выключен»;
  - на время остановки блокирует `play`/`next`/`prev`/`seek` и запуск
    контента: новый звук отменял роспуск, и колонки оставались в группе.
- `SpeakerManager.snapshot()` подхватывает живую группу и показывает её
  активной, даже если состояние было потеряно. Кнопка «Стоп» доступна.
- `SpeakerClient.stopMultiroom()` (`op=16`, поле 3) добавлен как
  best-effort: прошивка `1.104.35` эту команду игнорирует, поэтому основной
  путь — пауза и `turnOffMultiroomAfterPauseMs` (~10 с). Команда больше не
  задерживает остановку на 5 секунд ожидания ответа.

## [1.2.1] — 2026-11-12

### Исправлено

- Замер синхронности переведён на живую позицию из `GET_STATE`. В нативной
  группе `GetMetaData` может отдавать `media_player_state_json.position`
  снимком момента старта трека (`val=0`), поэтому старый замер возвращал
  `no-position-data`. Теперь менеджер ~10 секунд опрашивает все колонки,
  ловит переход `position` на следующую секунду и сравнивает эти границы;
  в ответе появились `resolutionMs` и `source: 'get_state'`.
- В панели диагностики позиция колонки берётся из `GET_STATE`, метаданные
  используются только как запасной источник.
- Мастер для замера определяется по живому `multiroom.mode`, а не по
  устаревшему состоянию прошлой группы.
- Замер, который укладывается в разрешение опроса, больше не выглядит как
  реальный рассинхрон: подпись сообщает «в пределах точности замера».
- Добавлен тест успешного замера на двух mock-колонках: он ловит регрессии,
  при которых переходы секунд не записываются.

## [1.2.0] — 2026-11-12

### Добавлено

- **Нативный SberCast-мультирум** через `MediaCommand START_MULTIROOM`
  (op=16, cmd=8). Группу собирает прошивка локально, без облака и общего
  Сбер ID: мастер становится источником звука и опорой времени, ведомые
  переходят в `SLAVE` примерно за секунду. В интерфейсе — запуск/остановка,
  чипы «нативный мастер» / «нативный мультирум» и групповая кнопка.
- API нативного мультирума: `POST /api/multiroom/native/start|stop`,
  `SpeakerClient.startMultiroom()`, `SpeakerManager.startNativeMultiroom()` /
  `stopNativeMultiroom()`.
- **Панель диагностики мультирума**: роли `MASTER`/`SLAVE`, RTT, свежесть
  данных, смещение часов, версия UDP-протокола и рекомендация мастера.
- Read-only эндпоинты `GET /api/diagnostics`,
  `POST /api/diagnostics/clock`, `POST /api/diagnostics/sync`. Замер
  синхронности нормализует `position.tsMs` через `timestamp` ответа, поэтому
  расхождение часов колонок не искажает результат.
- `lib/diagnostics.js`: медиана, анализ рассинхрона по общим секундам трека
  и выбор лучшего мастера.
- `SpeakerClient.getMetadataBundle()`, `parseMetaInfo()`: разбор
  `udp_protocol_version`, `multi_room_service_info_json`,
  `device_group_info_json` и `media_player_state_json` с `position.tsMs`.
- `parseState()` отдаёт `timesync` и список SberCast-соседей `sbercast`.
- Клиентская поддержка PIN-сопряжения с экраном (`pairWithPin`, op=4–6) и
  статусов `INPUT_PIN_CODE` / `CONFIRM_PIN_CONNECT`.
- Директива `SHOW_YOUTUBE` (type=1) с `smartAppInfo`; экспериментальный
  `sendStarCommand()` (type=3) — по таймауту возвращает `null`.
- Разбор push-метаданных `request_data[18]`: смена трека, позиция и громкость
  без поллинга.
- Дополнительные опкоды протокола: ping, отмена/подтверждение PIN, gamepad,
  smart-app state, voice transport и IRD.
- Мок-колонка отдаёт диагностическую `GetMetaData`, `timesync` и `sbercast`.

### Изменено

- Основная кнопка мультирума запускает **только нативный режим**. Программная
  deeplink-синхронизация оставлена в API (`/api/multiroom/start|stop|leave`)
  как совместимый фолбэк и больше не используется интерфейсом.
- Документация: разделы о нативном мультируме, диагностике, PIN, директивах
  и ограничениях прошивки.
- Версия проекта поднята до 1.2.0.

### Исправлено

- `StarCommand` (type=3) больше не считается рабочим каналом управления:
  прошивка с PIN-токеном молча игнорирует его, включая allowlist-команды.
  `sendStarCommand()` не бросает исключение по таймауту.
- Обновлены тесты и мок-колонка под нативный мультирум и диагностику.

## [1.1.1] — 2026-11-07

### Исправлено

- Зависание переподключения колонок после потери связи. Внешний `close()`
  (например, после двух неудачных опросов состояния) не эмитил событие
  `closed`, поэтому supervisor навсегда оставался в ожидании обрыва: сайт
  работал, но колонки числились «в сети» и не отвечали до перезапуска
  процесса.
- `_handleClose()` теперь идемпотентно отправляет `closed` ровно один раз на
  соединение.
- Ожидание обрыва в supervisor дополнительно проверяет `client.connected`,
  поэтому потеря события больше не блокирует переподключение.
- Добавлены регрессионные тесты на внешний `close()` и автопереподключение.

## [1.1.0] — 2026-11-04

### Добавлено

- Bluetooth-панель на карточке колонки:
  - режим сопряжения (`op=22`) — колонка становится видимой как A2DP-приёмник;
  - список спаренных устройств (`op=19`) с именем, MAC и статусом подключения;
  - подключение, отключение и удаление устройства (`op=20`);
  - скан устройств рядом (`op=21`) с уровнем сигнала RSSI.
- `decodeRepeated()` в TLV-кодеке для protobuf-полей `repeated`.
- Парсеры `parsePairedBt()` / `parseScannedBt()`.
- REST API для Bluetooth: `/api/speakers/:id/bluetooth`, `/bluetooth/discoverable`,
  `/bluetooth/scan`, `/bluetooth/command`.
- Мок-колонка поддерживает Bluetooth-опкоды — сценарий можно проверить без железа.
- Тесты: парсеры BT, TLV `decodeRepeated`, e2e Bluetooth на мок-колонке и UI-диалог.
- Скриншот интерфейса в README.
- CI на GitHub Actions (`npm test`).

### Изменено

- README дополнен разделом Bluetooth, описанием опкодов и ограничений.
- Версия проекта поднята до 1.1.0.
